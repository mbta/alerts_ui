## Summary

The ticket reports that Ferry • Delay alerts for Boat-F2H (Hingham/Hull Ferry) should produce `informed_entity` entries for both `Boat-F2H` and `Boat-F1` (Hingham Ferry), since F2H serves Hingham alongside F1. The fix was implemented in `AlertBuilder.add_special_combo_routes/2` which now adds `Boat-F1` when `Boat-F2H` is selected.

**AC:** When an alert is created with route Boat-F2H selected, both `Boat-F2H` and `Boat-F1` should appear as `informed_entities`. This should be true for **both trip-based and non-trip-based** Ferry alerts.

**Finding:** The fix works for non-trip-based alerts (route-only selection, the scenario described in the Steps to Reproduce). However, when a specific trip is selected (trip-based / `:RDT` combination), only `Boat-F2H` appears in the feed — `Boat-F1` is absent. The AC explicitly requires both cases to be covered.

## Skeptic pass

1. **Re-read feed directly** after creation — confirmed no Boat-F1 for trip-based alert 1000013 in both `alerts_feed_enhanced.json` and `alerts_manager_feed_enhanced.json`. The evidence is unambiguous.
2. **Code inspection** — `AlertBuilder.build_informed_entities(:RDT, ...)` (line 906 of `alert_builder.ex`) builds one entity per trip from `trip_information_by_id`, using the trip's own `route_id`. The `add_combo_routes` step (which adds Boat-F1) operates on `routes` before reaching `build_informed_entities`, but for the `:RDT` path the trip route_id is used directly and combo routes are not reflected. This matches the observed feed output.
3. **Non-trip case challenged** — created 4 separate non-trip Boat-F2H alerts (1000009–1000012) each independently confirmed to have both Boat-F2H and Boat-F1. The fix is real and stable.

No iteration cap hit (Driver→Adjudicator loop ran once, Skeptic ran one pass).

## Notes / blockers

- The Steps to Reproduce in the ticket only cover the route-only case (no trips) and use dev-green. Since dev-green is read-only, verification was done on local. The code path is identical between environments.
- No Boat-F2H alerts existed in the dev-green feed at time of original test (9 entities, 0 with Boat-F2H); at re-check time 12 entities, still 0 with Boat-F2H.
- The trip-based gap is in `AlertBuilder.build_informed_entities(:RDT, ...)` — for trip-based alerts, combo routes are not applied to the per-trip entity construction. Whether Boat-F1 needs a matching trip entity or a route-only entity is an open design question.
